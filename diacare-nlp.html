Support Message Classification

OverviewApproachResultsData & next steps

01Project overview

I built a standalone support-message classification prototype using 630 synthetic messages. It suggests one of five categories—appointment, billing, medical, technical issue, or other—and a priority label from 1 to 5 for human review.

My work connects text preprocessing, two separately trained classifiers, a deterministic keyword override, and a FastAPI service. The repository includes training code, saved models, evaluation results, API tests, and Docker packaging.

02How I built it

  1. Represent the message text. Convert words and two-word phrases into TF-IDF features, capped at 20,000. Each classifier uses a pipeline that learns its TF-IDF vocabulary within the training folds, preventing vocabulary leakage into the held-out folds.
  2. Learn category and priority separately. Train linear SVM classifiers with balanced priority weights. Group duplicate and related messages into 84 reviewed families, then reserve one shared holdout of 140 messages from 17 families. Train on the remaining 490 messages from 67 families; fit sigmoid calibration using three family-disjoint training folds.
  3. Expose a reviewable response. Check a short list of keyword patterns before model inference. A match returns category “medical” and priority 5; otherwise, the API returns both model predictions and indicative terms. A readiness endpoint returns HTTP 503 if either model is unavailable.

Engineering decisions

Separate classifiers let topic and priority be evaluated independently instead of assuming that a message’s subject determines its urgency. The keyword override is visible in the response through a gate_triggered field, so a reviewer can distinguish a rule match from model output.

Process liveness and readiness are separate: /health reports models_loaded, while /ready and prediction requests return HTTP 503 when models are unavailable. Model responses expose separate category and priority confidence fields; rule responses identify the matched phrases and leave both confidence fields empty.

03Results

On the corrected shared holdout, the models achieved 77.1% category accuracy and 55.0% priority accuracy. Both answers were correct on 63 of 140 messages (45.0%). The complete API, including keyword overrides, correctly returned both labels on 65 of 140 (46.4%).

Evaluation correction. These results replace the preliminary 92.9% and 80.2% figures, whose separate holdouts each contained seven training-overlap messages. The new shared split keeps annotated families and normalised duplicate texts entirely separate.

The priority model correctly classified 0 of 11 priority-5 messages; the API correctly classified 2 of 11. Its two keyword matches fixed two joint errors on this holdout. These outcomes do not support dependable urgent-message handling.

Keyword responses identify prediction_source and rule_matches, with both confidences set to null. Calibration alone does not establish probability reliability; that still needs its own evaluation. Indicative terms come from one ensemble member and do not fully explain the ensemble.

04Data, limitations & next steps

The category-balanced dataset contains 630 synthetic rows and no patient records. All rows have published family annotations, source hashes, and split assignments. The first fold of a five-fold grouped splitter with seed 42 was fixed before fitting, without searching for favourable scores. Families have unequal sizes, so the shared holdout contains 22.2% of rows. The intent-family annotations were prepared with coding-assistant support and await independent review; they are not proof that every paraphrase relationship has been captured.

The earlier independent row-level holdouts each included seven messages whose text also appeared in training. Those scores are archived and superseded. Both the split and calibration protocol have changed, so the lower scores cannot be attributed to duplicates alone. The current result remains one synthetic family-held-out experiment; the narrow keyword gate does not make it a validated clinical routing system.

Takeaway & next step. Grouping related messages revealed weak priority generalisation that the earlier experiment obscured. The immediate next step is an independent review of families and labels, followed by representative data and a fresh final test set before selecting improvements. Rare priorities, negation, unfamiliar wording, and confidence reliability need explicit evaluation with qualified reviewers. The current holdout will not be reused to tune the model or keyword rules.
